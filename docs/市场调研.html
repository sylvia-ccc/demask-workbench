00摘要

市面上不缺脱敏产品，缺的是为"人对着聊天框干活"设计的脱敏产品。

现有工具可以清晰分成四层：数据库脱敏平台、文档 PII 识别服务、AI 网关、终端 DLP。它们各自解决了一个明确问题，但都建立在一个假设上——数据在系统里、流向是可枚举的。而咨询顾问的真实工作流是：从客户那儿拿到一堆 Excel 和访谈记录，在本地写成 Word/PPT，遇到卡壳就把一段话复制进 ChatGPT、Claude 或豆包。

这条链路里，数据既不在数据库，也不经过任何可被网关拦截的 API。它是剪贴板。

因此本报告的结论是：不要买一套企业级 DLP 来解决这个问题（重、贵、且管不到剪贴板），也不必从零攒开源库。合理路径是先做一个本地轻量工作台，把"脱敏—发给 AI—还原"这条链路做顺，等团队规模上来再补网关和策略中心。报告附带的工具即按此思路实现，可直接使用。

三个最关键的判断 ① 咨询场景的核心敏感信息不是身份证号，而是客户名称、项目代号、交易金额、未公开财务数据——绝大多数 PII 工具对后四类几乎无感。
② 你要的是可逆脱敏：企业级产品追求"不可还原"，但你的交付物必须还原成真名，方向相反。
③ 只改名字不够。金额和结构本身就是指纹，必须一起处理，否则行研的人三分钟就能反推。

01问题定义：你要防的不是身份证

三类风险，权重完全不同

风险类型具体内容泄露后果现实频率
个人信息 身份证、手机号、银行卡、住址、访谈对象姓名与职务 违反《个人信息保护法》，行政处罚 + 民事赔偿 中
商业机密 客户名称、项目代号、未公开财务、报价与折扣、并购标的、组织人事 违反 NDA，丢客户、赔款、行业口碑受损 极高
可推断信息 行业 + 地域 + 规模 + 时间 + 渠道结构的组合 即使删掉名字，仍能唯一定位到具体企业 高，且最常被忽略

关键洞察：匿名化的边界是可识别性，不是名字

下面这段话，把公司名去掉之后，你觉得还安全吗？

"某华东区域乳制品企业，2025 年营收 128.6 亿元，线上 GMV 占比 26.6%，2027 年 3 月与主要供应商合同到期，全国门店约 1,240 家。"

对任何做过消费行业研究的人来说，这四五个数字的组合基本等价于公司名。这在数据保护领域叫准标识符（quasi-identifier）——单个字段不敏感，组合起来唯一可识别。

这就是为什么"把客户名换成客户 A"的脱敏方式在实践中经常失效。真正有效的处理必须同时动结构：把金额按统一比例缩放、把绝对数改成区间、把精确日期改成季度。缩放之后，比例关系（毛利率、线上占比、增速）全部保留，AI 照样能算，但指纹被破坏了。

由此推出四条功能要求，也是后文评判所有工具的标准：
① 能识别中文商业实体（公司、项目代号、人名），不只是证件号；
② 可逆，且还原要能容忍大模型改写；
③ 能对数值做保结构变换，而不只是打码；
④ 全流程留在本机，不产生新的数据出境。

02市场格局：四类工具与代表厂商

按"拦截位置"划分，市面上的产品可以归为四类，另有合成数据作为补充路线。

第一类　数据库静态 / 动态脱敏平台

代表：美创科技、闪捷信息、安恒信息、启明星辰、天融信、天空卫士、明朝万达、亿赛通、神州数码、国投智能（美亚柏科）；国外 Oracle Data Masking、Delphix、Immuta、Protegrity、Informatica。

强项：字段级规则成熟，脱敏后保持主外键与统计特征一致，支持可逆脱敏与权限化动态脱敏；对"开发测试取数""数据共享交换"这类场景是标准答案。

短板：整套体系围绕数据库与数据中台构建，交付周期以月计，按库/节点/模块计价，量级通常在十万至百万每年。而咨询顾问的分析稿、访谈纪要、PPT 里的表格，根本不在这类产品的覆盖范围内。

第二类　文档 / 文本 PII 识别与脱敏

代表：Microsoft Presidio（开源，MIT）、AWS Comprehend、Google Cloud DLP、Nightfall AI、Private AI、Skyflow、Tonic Textual、Gretel；开源侧还有 Protect AI 的 LLM Guard（内置基于 Presidio 的 Anonymize 扫描器）。

强项：实体识别能力强，支持自定义识别器，可容器化私有部署，能处理自由文本与部分文档格式。

短板：

  • 以"个人信息"为中心设计。Presidio 内置识别器以欧美证件（SSN、信用卡、IBAN）为主，中文人名与机构名需要自行接入中文 NER 模型，效果依赖调优；"启明星项目""华润万佳"这类商业实体基本识别不到。
  • 多为 API 形态。用它的云服务，意味着数据仍然要出本机——只是换了一个接收方。
  • 不可逆或还原成本高。设计目标是"抹掉"，不是"还能换回来"。

第三类　AI 网关 / 大模型防火墙

代表：Kong AI Gateway、Cloudflare AI Gateway、F5 AI Gateway（Guardrails 能力来自 2025 年收购的 CalypsoAI）、Portkey、LiteLLM；国内腾讯云 LLM-WAF、奇安信、绿盟、瑞莱智慧等的大模型安全网关产品。

强项：统一入口、密钥托管、限流计费、提示注入防护、全量审计日志，部分产品内置输入输出双向脱敏。这是企业"把 AI 用起来又不失控"的正确基础设施。

短板：它只能看见 API 调用。你在 ChatGPT / Claude / 豆包 / Kimi 的网页版里选中一段文字按 ⌘V，网关一无所知。而对个人和小团队来说，网页版恰恰是主要用法。此外这类产品要求你改造调用方式、通常按流量计价，个人顾问用不上。

第四类　终端 DLP / CASB

代表：天空卫士、亿赛通、明朝万达；国外 Zscaler、Netskope、Forcepoint。

强项：能拦住"复制到网页""上传到网盘""外发邮件"，有完整审计链路，是合规检查的硬指标。

短板：误报高、弹窗多、体验差。它只"堵"不"疏"，结果是顾问用手机拍屏幕、用个人账号、用没装客户端的设备绕过去——风险没消失，只是从可见变成不可见。

补充路线　合成数据

代表：Gretel、Mostly AI、Tonic。

适合"我要一份能拿去训练模型/做演示的数据"，不适合"我这份报告的第三段想让 AI 帮我改一版"。生成合成数据本身需要原始数据进入工具，且无法还原，与咨询交付的需求不匹配。

03为什么现成工具都不顺手

把上面四类产品放进同一个工作流里看，会发现五种系统性错配：

错配工具假设你的现实
位置错配数据在数据库、在 API 流量里数据在 Word、Excel、PPT 和剪贴板里
实体错配敏感 = 身份证、手机号、银行卡敏感 = 客户名、项目代号、金额、未公开财务
方向错配脱敏要不可逆，防止还原交付物必须还原成真名
语义错配把数字替换成 *** 就安全了数字被抹掉，AI 就没法帮你算 CAGR、做敏感性分析
成本错配按节点/流量/席位计价，十万起个人或三五人团队，预算与运维能力都有限
一个容易被忽略的事实 在网页版大模型里，"复制粘贴"这个动作本身就是一次数据出境，而且不留下任何企业侧日志。任何只覆盖 API 流量的方案，对这条路径都是盲的。这是本方案把着力点放在"复制之前"的原因。

05建议方案：三层架构，分阶段落地

不要一步到位。按"人 → 团队 → 组织"三个阶段推进，每阶段都有独立价值。

LAYER 1 · 现在 个人工作台 本地脱敏 + 可逆还原。解决"我今天就要把这份纪要发给 AI"。
LAYER 2 · 5 人以上 团队策略中心 统一词库、映射库加密托管、使用审计。解决"不同人脱敏口径不一致"。
LAYER 3 · 有合规要求 AI 网关 + DLP 所有模型调用走代理，自动脱敏/还原，异常外发阻断。解决"审计能过"。

Layer 1 为什么是本地工具，而不是 SaaS

逻辑很简单：脱敏工具本身不能成为新的泄露点。如果脱敏要先把原文上传到某个云端服务，那只是把风险从 A 公司转移给 B 公司。因此这一层必须满足"零网络请求、零依赖、可离线运行"。

技术选型上，本方案刻意只使用 Python 标准库：单个文件、双击即用、不需要 pip install、不会因为依赖冲突跑不起来。对非技术背景的顾问来说，这一点比任何算法指标都重要。

Layer 3 什么时候必须上

  • 客户合同里明确要求"AI 使用需可审计"；
  • 团队超过 20 人，无法靠自觉保证口径一致；
  • 开始用私有化模型（此时网关的价值从"防泄露"转为"统一治理"）。

06合规边界（非法律意见）

法规与本场景相关的要点
《个人信息保护法》
第 4 条、第 73 条		 第 73 条区分两个概念：去标识化——不借助额外信息无法识别特定自然人；匿名化——无法识别且不能复原。匿名化后的信息不属于个人信息，去标识化后的仍属于。
推论：本工具是可逆的，法律性质上属于"去标识化"，处理后的文本仍是个人信息，仍受个保法约束。它的价值是显著降低泄露风险与责任，而不是让数据"变成非个人信息"。任何声称"一键匿名化、从此不受监管"的产品都值得警惕。
《数据安全法》 要求建立数据分类分级保护制度。实操上应至少区分"可外发 / 需脱敏 / 禁止出本机"三档，并在项目启动时就标注。
《网络数据安全管理条例》
国务院令第 790 号，2025-01-01 施行		 细化了个人信息处理规则、重要数据识别与申报、跨境提供安全评估。把客户数据贴进境外模型服务，可能同时触及"向第三方提供"与"数据出境"两条线。
《生成式人工智能服务管理暂行办法》 对服务提供者提出训练数据与内容责任要求。对使用方而言，更现实的是合同义务：多数客户 NDA 约定"未经书面同意不得向第三方披露保密信息"，把内容输入公有云大模型是否构成"披露"，目前司法实践尚无统一结论，但风险敞口是实在的。
三条实操红线（比任何工具都重要）
① 原始数据、可反推的组合数据，一律不进公有云模型；
② 项目启动时在 engagement letter 里写明 AI 使用条款与脱敏措施，把"是否允许"变成白纸黑字；
③ 保留脱敏与还原的操作记录，出问题时能证明"已采取合理措施"。

07已交付的工具

按上述思路实现了一个可运行的工作台，核心是把"脱敏—发给 AI—还原"做成一条顺手的链路，而不是一个需要学习的安全系统。

交付形态：一个 HTML 文件 不装 Python、不装客户端、不连服务器——整个工具是一个 81 KB 的 .html，双击用浏览器打开即可。发给同事就是发一个附件，微信、邮件、共享盘都行，对方不需要任何准备。
这个选择不只是为了省事：如果脱敏工具要求"先把原文上传到某个服务"，它自己就成了新的泄露点。单文件 + 浏览器本地计算，是唯一能同时满足"零安装"和"零外发"的形态。

六个设计决定

决定理由
代号用【企业A】实测中，中文方括号内的内容被大模型改写的概率最低。模型可能把"客户A"改写成"该客户"，但很少动【】里的东西，这直接决定还原成功率。
金额等比缩放默认 ×0.618。所有金额同比例变化，增速、占比、弹性、敏感性分析结果不变，但绝对值指纹被破坏。需要精确计算时切回"原样保留"，改用区间化或纯代号。
映射库落本地存于工具目录下的 vault/，不上传、不同步。提供"新建会话"一键重置编号，避免不同项目串号。
还原要容错同时匹配【企业A】、企业A、__ORG_A__ 三种形态。模型把括号吃掉、加了空格、换成全角，都能还原。
给置信度，不假装全对每条识别结果标注依据（后缀识别 / 角色词 / 校验位 / 词库）与置信度。低置信度的让人扫一眼，比宣称 99% 准确更负责。
单文件交付引擎、界面、Office 文件解析（浏览器原生解 zip）全部装进一个 HTML，映射存浏览器本地。零安装是"能不能被真正用起来"的分水岭——要求装环境的工具，在咨询团队里通常活不过一周。
残留检测脱敏后再扫一遍：还有没有 11 位数字、18 位数字、邮箱、密级标识。漏了会亮黄条，而不是静默通过。

还原：把 AI 的答案变回人话

这是整个工具真正的价值点。发给 AI 的是代号，拿回来的分析结论必须能直接进交付文档。

使用方法

STEP 1双击打开双击 HTML 文件，用 Chrome / Edge 打开，不装任何东西。
STEP 2粘贴或拖入支持 .docx / .xlsx / .pptx / .txt / .md / .csv，直接拖拽。
STEP 3扫一眼清单确认没有误伤，把不该脱的"放行"，漏掉的加进词库。
STEP 4复制给 AI一键复制，粘到任何大模型。此时流出的只有代号。
STEP 5还原把回复贴回"还原"页，一键换回真名，直接进报告。

08效果、局限与演进

诚实的能力边界

做得住的
手机号、身份证、银行卡、统一社会信用代码、邮箱、IP/内网地址、车牌——规则 + 校验位，接近 100%。
带后缀的企业名（有限公司、集团、银行、事务所…）——中等偏上，泛称已过滤。
角色引导的人名（"项目经理 李明""联系人：张伟"）——较可靠。
做不到的
无后缀的简称与内部黑话（"老东家""那个乳企"）——必须靠词库。
扫描件 PDF、图片里的文字——需 OCR，当前不支持。
复杂嵌套表格的单元格语义——抽取为文本后可能错位。
模型自行发明的"客户甲"等新称谓——无法还原，需人工替换。

因此工具的设计不是"自动完成"，而是"把该看的都摆出来，让人 30 秒确认"。在脱敏这件事上，一个宣称全自动的系统比一个诚实的检查清单更危险。

后续可以加的（按性价比排序）

  1. 浏览器插件：监听输入框粘贴事件，在内容进入 ChatGPT 之前自动替换，用完在页面上还原。这一步能把"要记得先脱敏"变成"不可能忘记"。
  2. 剪贴板守护进程：常驻后台，复制长文本时弹一个小条提示"检测到 3 处疑似敏感信息，已脱敏"。覆盖所有应用，包括微信。
  3. Office 插件：在 Word / PPT 里选中一段直接"发送到工作台"，处理完回填。
  4. 团队词库同步：客户名、项目代号由项目负责人维护，全员共享，避免各自为政。
  5. 中文 NER 模型接入：用小型本地模型替换规则，提升无后缀实体召回。代价是启动变重，建议做成可选插件。
一句话结论
这个问题的本质不是"买什么脱敏软件"，而是"在数据离开你手指之前的最后 10 厘米，装一道自己能控制的闸门"。企业级产品覆盖不到这里，开源库要自己攒，所以最合理的做法是自己搭一个足够小、足够顺手的本地工具——然后用团队策略和网关去补它管不到的地方。

09怎么发给同事用

工具做得再好，如果对方要"先装个 Python"，实际使用率会掉到接近零。分发方式本身就是产品设计的一部分。

方式对方要做什么上手成本适用
单文件 HTML 保存附件 → 双击 → 浏览器打开就用 零 个人 / 小团队
内网网页服务 打开内网地址；需 IT 部署与运维 中 20 人以上

在线 SaaS 注册账号，把原文上传到别人服务器 低 与目标矛盾
"上云"有两种，只有一种是安全的 静态托管：服务器只负责把这个 HTML 发出去，计算仍然发生在每个人的浏览器里。安全性与离线文件完全相同，只是分发更方便、改一次全员生效。
服务端处理：把原文传到服务器再脱敏。此时你就从"使用者"变成了《个人信息保护法》下的个人信息处理者，要承担存储、加密、访问控制、泄露报告的全部责任。风险没有消失，只是从 AI 厂商转移到了你自己身上。

静态托管的残余风险是下发链路被篡改——页面正好处理最敏感的数据，一旦服务器被入侵、HTML 被植入窃取代码，等于把后门直接发给了全员。缓解办法很简单：HTTPS、只允许内网访问、发布前把文件哈希发到群里让同事核对，页面上也留了版本号。

发送时的五个实操细节

  1. 压缩成 zip 再发。部分邮箱和企业微信会拦截 .html 附件，zip 几乎不会被拦，也避免对方在聊天窗口里直接预览成一堆代码。
  2. 让对方在电脑上打开，别用手机。手机微信的内置浏览器不能正常运行本地文件。电脑上双击，Chrome / Edge 都可以；Mac 上 Safari 需 16.4 以上，建议直接指明用 Chrome。
  3. 随附三句话说明：① 这是纯本地网页，可断网使用；② 数据只在你自己的浏览器里，不会上传；③ 打开后点"看示例"先看效果。
  4. 第一次用先跑示例。比任何说明书都有效——看到 128,600 变成 79,475、毛利率还是 23.8%，概念立刻就懂了。
  5. 提醒映射表的边界。映射存在各自浏览器里，不跨设备。换电脑前先"导出映射"，否则之前发出去的内容还原不回来。
一个容易被忽略的信任问题
同事收到一个陌生 .html 文件，第一反应往往是"这会不会是病毒"。所以随附说明里要讲清楚：单文件、无外链、无网络请求，可以断网打开验证。能离线运行，本身就是最好的安全证明。
