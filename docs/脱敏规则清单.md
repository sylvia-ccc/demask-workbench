# 脱敏规则清单（v2.2）

> 这份清单记录工具**会脱什么、怎么认出来、刻意不脱什么、脱完怎么换、怎么还原、怎么兜底**。
> 每条规则都能在 `src/engine.js` 里找到对应代码，在 `src/testset*.json` 里找到对应用例。
> 标 🆕 的是 v2.0 新增或修复的规则。

---

## 一、识别：会脱什么

### 1. 机构（ORG）

| 方法 | 说明 | 例子 |
|---|---|---|
| 全称后缀 | 有限公司、股份有限公司、集团、银行、证券、基金、信托、事务所、研究院等 35 个后缀，向左回溯出完整名称 | 深圳优鲜科技有限公司 |
| 内置词库 | 9 个行业，674 个没有后缀的简称；可以按行业开关 | 宁德时代、高盛、KKR |
| 两字简称 | 美的、小米这类歧义大的词，只在上下文明确时才认 | "美的集团营收"脱，"美的东西"不脱 |
| 引导词 + 行业后缀 | 合作方为 / 供应商是 / 甲方为 + XX科技、XX供应链 | 供应商为百佳供应链 |
| 列举 | 顿号列出的同类机构 | 中信证券、中金公司、华泰证券 |
| 声明简称 | 以下简称 / 下称"XX" | （以下简称"优鲜"） |
| 简称归并 | 全称和简称共用一个代号 | 华润万佳 ↔ 万佳 → 都是【企业A】 |
| 英文实体 | 有 Inc / Ltd / LLC / Capital / Partners 等后缀才认 | Northpeak Capital |
| 表格列 | 表头是"客户名称、供应商"的列 | 前五名客户表 |
| 用户词库、自定义规则 | 手动加词；正则加捕获组 | 内部客户代码 |
| 🆕 泛指排除 | "客户证券账户、对方银行、本基金、某保险"不算具体机构 | — |
| 🆕 地名品牌 | 王府井、西单、国贸等，后面接店 / 商圈 / 一带时按地名处理 | "王府井店"不脱 |
| 🆕 v2.1 股权语境 | 控股股东、机构股东、关联方之后的名单；子公司 / 母公司后必须跟"为 / 包括" | 控股股东双欣化工；机构股东还包括蒙兴基金、华鑫信托 |
| 🆕 v2.1 投资对象 | 对 X 的（某轮）投资 / 增资 / 估值；排除项目、行业、赛道、人才等泛指 | 对天泽生物的 C 轮投资 |
| 🆕 v2.1 名单扩散 | 顿号名单里已确认机构至少占一半，其余项也按机构处理；排除城市、人名、职务、科目 | 蒙兴基金、中信金融资产、华鑫信托 |
| 🆕 v2.1 外国公司 | 带地区括号的 Limited；PT …、… SDN BHD、… TBK | CDH Investments Management (Hong Kong) Limited |

| 方法 | 置信度 | 例子 |

| 角色引导 | 0.9 | 项目经理 李明、联系人：张伟 |

| 括号别名 | 0.85 | 张伟（张总） |
| 称呼 | 0.8 | 李娜您好 |
| 语境动词 | 0.75 | 由张伟、对接王芳 |
| 后置动词 | 0.72 | 张伟负责、王芳表示 |
| 英文语境 | 0.85 | prepared by John Smith |
| 🆕 强引导 + 名单 | 0.9 / 0.88 | 独立董事：冯晓光、蒋一帆、上官静；实际控制人为邓志远；分别为：戚家豪（首席科学家）、施雨桐 |
| 🆕 由…担任 | 0.9 | 监事会主席由孙卫东担任 |
| 🆕 履历开头 | 0.92 | 欧阳楚英，1971年出生，中国国籍 |
| 🆕 履历动词 | 0.88 | 司马文涛曾任职于 / 现任 / 历任 / 毕业于 / 辞去 |
| 🆕 姓 + 职务简称 | 0.82 | 王总、张总监、李总工、刘董、潘先生、小刘、老陈（"40小时"这类数字后的不算） |
| 🆕 邮件称呼和签名 | 0.88 | Hi 思远；Dear Mr. Tanaka；Best, Grace Lin；CFO Linda Wu |
| 同名扩散 | 0.9 | 置信度 ≥0.88 的名字，全文其他出现处一起脱 |
| 别称归并 | — | 张总 → 与张伟同一个代号 |

**姓氏表 🆕**：原来约 100 个单姓，"柯、戚、施、詹"这类全部漏掉。v2.0 分两档：
- **常规档**：168 个，任何规则都认。
- **强引导档**：82 个也是常用字的姓（管、时、明、华、路、季、纪、项、施、谈……），只在职务、名单、称谓、"由…担任"之后才认；即便如此，以常用词开头（时间、管理、华为……）或以"层、组、区、部"收尾的也不认，避免把"管理层、项目组、季度复盘"当成人名。

**复姓**：欧阳、司马、上官等 28 个。复姓名字可以到 4 个字（欧阳楚英），不会被截成"阳楚英"。

**取名长度 🆕**：先试 3 字再试 2 字，以"后面紧跟的是不是名字之后常见的字词"（标点、先生、表示、担任……）为准。所以"李娜表示"取"李娜"，"王立平表示"取"王立平"。

### 4. 金额与财务数据（MONEY / PCT）

| 方法 | 说明 |
|---|---|
| 货币或单位 | ¥、$、人民币、USD + 数字；数字 + 亿 / 万 / 元 / million / bn |
| 财务语境 | 前后 14 个字内有营收、净利、估值、对价、AUM 等 100 多个科目词 |
| 科目行 | "营业收入 128,600"这种表格行 |
| 🆕 v2.1 同行金额 | 同一表格行已有"金额 + 占比"时，其余千分位数字也按金额；行首是人数、门店、股数时不算 |
| 表头列 | 2024A / 2025E 这类年份列下的数字 |
| 括号负数 | 净利润(1,234)万元 |
| 中文大写 | 人民币壹仟贰佰万元整 |
| 股权比例 | 持股 35%、转让 20% 股权（默认脱） |
| 其他比率 | 毛利率、增长率（默认**不脱**，比率是 AI 做分析需要的） |

**不算金额的情况**：
- 百分比；
- 年月日；
- 序号、季度（第 3、Q3、H1）；
- 四位年份；
- 🆕 数字后面跟量词的（人、家、台、吨、平方米……），数字和单位之间有空格也能判断（"4.2 万平方米"）。

## 一.5、疑似实体候选（v2.2，不自动替换，交给用户确认）

| 语境 | 例子 |
|---|---|
| 履历 | 于迈瑞电子担任副总裁 |
| 持股路径 | 通过安特尔、双欣资源和洪湖聚智间接持有 |
| 上市主体 | 海岚医疗拟在科创板上市 |
| 口语指代 | 跟龙腾那边 |
| 英文名 + 公司 | Marcadia Biotech 公司 |
| 集团关系 | 子公司苏州恒达的 |
| 行业词尾短名 | 蓝鲸新材、星河光电 |
| 引号名称 | 项目代号叫"青松" |
| 只有名的称呼 | 晓峰补充说 |
| 孤立英文名 | 和 Mark 对齐 |

这些写法如果自动替换，误伤会很多（"于今年担任""跟财务那边""通过协议持有"）。所以只列为候选，并预先过滤掉时间词、泛称、部门、城市、常用词和数量短语。用户点了"不是"的候选，会按项目记住，以后不再提示。

## 一.6、PDF 导入（v2.3）

PDF 本身不参与识别规则，导入时先还原成文本，再走上面全部规则。还原方式决定了会不会漏脱，所以单列：

| 处理 | 做法 | 为什么 |
|---|---|---|
| 只读文字层 | 不做 OCR；扫描件直接拒绝 | 识别错的字比没有字更危险：错字既脱不掉，也看不出来 |
| 字体编码 | 先查字体自带的 ToUnicode 表，再查预置编码（UniGB-UCS2 / UTF16、GBK-EUC 等），最后按单字节编码 | 中文 PDF 几乎都用字形编号存字，不还原成字符就什么都识别不了 |
| 表格 | 同一行里间隔超过约 1.6 个字宽，插入制表符 | 让金额列按"表格列"识别和缩放 |
| 折行 | 排满一行、没有句末标点、下一行从左边界开始的，拼回去；表格单元格里左对齐、像"没写完"的折行拼回去；行首是逗号句号、或以"有限公司 / 责任公司"开头的必定拼回 | 公司名被折成两行，前半截会漏脱 |
| 跨行识别（引擎） | 换行两侧拼起来再识别一次，跨过换行、以"有限公司"这类强后缀结尾的才算；最多跨 3 个短行 | 版面还原难免有拼不回的，引擎再兜一层底；从别处复制来的断行文本同样受益 |
| 重复绘制 | 同一位置描了两遍的字（伪粗体）只保留一次 | 否则会出现"宁宁德德时时代代" |
| 旋转文字 | 整页旋转 90°/180°/270° 的照常读取；斜着的（水印）不输出 | 横排的宽表格常整页旋转；斜着的往往是"仅供内部使用"一类水印 |
| 读不到字的页 | 导入后提示页码 | 扫描页夹在正常文档里时，不提示会让人以为整份都处理了 |
| 恶意文件 | 解压大小、单页内容、表单调用次数、字符串长度都有上限 | 一个 1MB 的"压缩炸弹"可以解成 1GB，把浏览器卡死 |
| 加密 | 只支持空打开密码（RC4 / AES-128 / AES-256）；有打开密码的拒绝 | 研报常见"禁止复制"加密，这类文件本来就能打开阅读 |

## 二、刻意不脱什么（以及为什么）

| 不脱 | 原因 |
|---|---|
| 比率、百分比（默认） | 这是 AI 做分析的依据；需要时可以打开"其他比率" |
| 年份、季度、普通日期 | 不指向具体的人或机构；出生日期除外 |
| 职务、部门、会计科目、法规名称 | 没有识别性，而且 AI 需要靠它们理解上下文 |
| 行业泛称（标的公司、并购基金、头部企业） | 泛指不是具体机构 |
| 门店数、员工数、产能、面积 | 不是金额，缩放之后会让 AI 算错 |
| 版本号、日志时间戳、哈希、请求 ID | 不指向具体的人或机构，脱掉反而让 AI 读不懂技术材料 |
| 密码占位符（******、your_password） | 本来就不是真值 |

## 三、替换：脱完是什么样

| 方式 | 结果 | 能否还原 |
|---|---|---|
| 代号（默认） | 【企业A】【人物B】，按项目隔离、从 A 开始编号 | 能 |
| 下划线、纯文本 | \_\_ORG_A\_\_、企业A | 能 |
| 掩码 | 华润\*\*\*、138\*\*\*\*5678 | 不能 |
| 金额等比缩放（默认） | 所有金额乘同一个系数（默认 0.618，每个会话随机），比率不变 | 能 |
| 区间化、等长乱数、原样保留 | 按需选择 | 区间化不能，其余能 |

同一个数的不同写法（128.6、128.60）得到同一个结果；同一个实体的全称和简称共用一个代号。

## 四、还原

- 兼容 AI 的 9 种改写：去掉括号、加空格、markdown 加粗、改成半角方括号……
- 还原金额时校验单位：79.5% 不会被还原成营收数字；79.5 亿被 AI 改成 79.5 万时也不还原。
- 代号属于别的项目时会提示"看起来属于项目 X，切过去重新还原"。

## 五、兜底

1. **残留扫描**（脱敏之后再查一遍）：手机、身份证、邮箱、16–19 位长数字、密级标识；🆕 国际电话、平台密钥、密码。同一处只报一次。
2. **复制拦截**：残留扫描有命中时，复制前先提示。
3. **再识别风险**：名字脱掉之后，再看行业、地域、规模、结构特征还剩多少线索（"名字已脱 · 描述仍可反推"）。
4. **审计记录**：只记元数据，不记正文。

## 六、设计原则

### 1. 按识别能力分级，而不是按"像不像隐私"

| 级别 | 含义 | 本工具的类型 | 处理 |
|---|---|---|---|
| 直接标识符 | 单独出现就能指向某个人或某家机构 | 机构名、人名、身份证、手机、邮箱、银行卡、证券账户、统一社会信用代码、股票代码 | 一律替换，可还原 |
| 准标识符 | 单独不够，几个组合起来就能反推 | 金额（体量）、地址、出生日期、项目代号、行业 + 地域 + 规模 + 结构特征 | 金额等比缩放、地址和日期替换；剩下的描述性线索由"再识别风险"提示 |
| 分析属性 | AI 做分析需要，本身不指向谁 | 比率、增速、占比、职务、会计科目、年份 | 默认保留 |

脱敏的目标不是"替换掉看起来敏感的词"，而是**让材料无法被反推到具体主体，同时保住分析价值**。

### 2. 识别要可验证
有校验位的一律校验：身份证、统一社会信用代码、银行卡、IBAN。没有校验位的必须有语境：护照、账号、SWIFT、合同编号。宁可要求语境，也不让一串普通数字被误判。

### 3. 只换值，不换结构
`password=Abc123` 只换掉 `Abc123`；"法定代表人柯振宇"只换掉人名。键名、职务、科目留着，AI 才看得懂这一段在说什么。

### 4. 识别和变换分开
同一批识别结果，可以输出成可还原的代号、不可还原的掩码、等比缩放或区间化，由使用场景决定，不改识别逻辑。

### 5. 确定性
同一个实体在同一个项目里永远是同一个代号；同一个数的不同写法缩放后结果相同；插入新实体不会打乱已有编号。AI 多轮对话、跨文档引用都不会串号。

### 6. 失败即拦截
解析出错、残留扫描有命中、代号属于别的项目时，明确提示并拦截复制，不悄悄放行。

### 7. 不联网由浏览器保证
页面内置内容安全策略（CSP），浏览器会拒绝一切网络请求。这不需要用户相信我们的承诺，按 F12 就能验证。

### 8. 只用封存数据报效果
规则调优只看开发集；对外报告的数字来自调优期间没看过的封存集。每个新版本还要和上一版做"误伤对比"：同一批中立文本中，新版本新增的识别必须都是对的。自建测试集上的 100% 不作为能力证据。

### 9. 规则到了上限就换方法
机构简称这一类，规则在开发集上涨很多、在封存集上涨很少，说明已经接近上限。下一步靠产品交互（疑似简称一键确认、项目客户名单导入），而不是继续堆规则。

## 七、已知局限（如实说明）

| 局限 | 说明 |
|---|---|
| 只有名、没有姓的称呼（晓峰、雪莹） | 规则无法和普通词区分。只要全文其他地方出现过全名，同名扩散能补上 |
