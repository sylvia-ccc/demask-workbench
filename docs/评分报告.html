01为什么要自己造评分卡

市面上的脱敏产品都说自己「准确率 95%+」，但没有一家公布可复现的评测口径。拿这个数字对标，等于拿广告对标事实。

能找到的唯一公开数据是开源 PII 模型的：bert-small-pii-detection 在自建测试集上 F1 0.87，换到没见过的外部数据集明显下降。这更接近真实水平——模型在自己训练过的数据上总是很好看。

所以这里的做法是：造带标注的测试集，跑出真实的 Precision / Recall，把每一项的得分依据摆出来。分数可以争论，但计算过程可复现：node src/eval.js 和 node src/score.js。

判定规则写在 eval.js 里，只有三条：

  • 期望脱敏的文本，脱敏后原文还完整出现 → 漏检（FN）。这是唯一重要的指标，漏一个就是风险。
  • 识别出的实体不在期望列表里 → 误报（FP）。
  • 要求保留的文本被改掉 → 过度脱敏，也计入 FP。

A 识别质量（45 分）

权重给得最高，因为漏一个敏感信息就是风险，误伤一片则是文档没法读。召回按 98% 为满分线，准确按 96% 为满分线——不给「100% 才算满分」的虚高标准，也不允许 90% 就混过去。

A1 = 25 × min(1, Recall / 0.98)
A2 = 20 × min(1, Precision / 0.96)

04这一轮修了什么

评分不是为了好看，是为了找出差距。这一轮从「盲测 P 90.8% / R 80.8%」修到当前水平，动了这些地方：

问题表现改法
竖线表格全漏 markdown / 飞书 / Notion 复制的表格是 | 分隔，整张表 0 识别 分隔符判定加竖线，并过滤首尾空单元格与 |---| 分隔行
多空格表格全漏 从 Word / 网页复制的是空格对齐，同样 0 识别 支持 \s{2,} 分隔，单元格偏移用位置切分重算
"元禾"被切断 苏州元禾控股 → 禾控股有限公司，因为"元"被当货币单位 只有"元"紧跟数字/亿/万时才算单位
三字品牌名失效 "比亚迪竞争"识别不了——27 个三字词被错放进"需上下文"弱词表 只有两字词才走上下文判断
引导词被一起吃 公告编号：2025-026 → 【编号A】，把"公告编号："也替换了 带捕获组的规则统一按 group 1 定位
括号负数全漏 利润表 (79,200) 原样保留，正数却脱了 单独识别括号负数，输出保持括号形式
同一数字两个值 128.6 → 79.5，128.60 → 79.47，AI 当成两个数 数值规范化后查表，单位参与 key
行业词误伤 "工程机械、船舶等行业"里的"船舶"被当公司 移除 26 个纯行业词；后跟"等/行业/领域"时不认
实体只脱一处 名单里脱了"张伟"，正文"会议由张伟主持"原样保留 同名扩散：识别出一处，全文同名一起脱
无后缀公司名 "合作方为优鲜科技"识别不了 引导词 + 行业后缀；列举里逐个提取
英文人名/公司名 John Smith、Acme Retail Holdings Ltd. 全漏 只在有称谓/动词引导时识别人名；公司名必须有 Ltd/Inc/Group 等后缀
PDF 断行无提示 公司名被切成两半，用户不知道要先整理 导入时自动检测断行数，超过 3 处高亮「整理断行」按钮

结论不是"比它们强"，而是"解决的不是同一个问题" 商用平台的假设是「数据在数据库和系统里」，本工具的假设是「数据在顾问的剪贴板里」。 前者能管住全公司，但覆盖不到一个人在网页版 AI 里粘贴一段访谈纪要；后者只能管一个人，但那正是最容易出事的地方。

06必须说清楚的三件事

① 100% 的识别率不可采信 三份测试集都参与过调优。留出集本来是"没见过的"，但我看了失败项之后又改了规则——它就不再是留出集了。 真实泛化能力应该看真实文档的抽样结果（下一节），以及你自己拿一份报告跑一遍。 任何声称 100% 的脱敏工具都在骗人，包括这份报告里的数字。
② 评分卡是我定的，权重可以争 "召回 25 分、准确 20 分"是我的判断：漏一个敏感信息比误伤十个词更严重。如果换成"误伤更不可接受"的权重，分数会变。 可争论的是权重，不该争论的是计算过程——eval.js 和 score.js 都在，你可以自己改权重重算。
③ 真实文档仍然会漏 拿宁德时代年报（11,219 字）实测：85 个实体，14ms，残留检测 0。但抽样核对能看到：
【宁波联合创新新能源投资管】
【理合伙企业（有限合伙）】
公司名被 PDF 断行切成两半——这不是规则问题，是输入问题。点「整理断行」能解决大部分， 但扫描件、图片、跨页表格仍然需要人工检查。

08你可以自己验证

所有数字都能复现：

cd demask/src
node eval.js testset.json # 基础回归
node eval.js testset-holdout.json # 留出验证
node eval.js testset-blind.json # 盲测
node score.js # 出总分
node bench.js # 性能压测
node test.js # 端到端 6 个场景

但最有说服力的验证不是跑我的测试集，而是拿一份你已经交付过的真实报告，跑一遍，数一下漏了几个。漏的通常集中在客户自己的内部叫法和行业黑话——把它们加进词库，以后所有文档都生效。
